## 🚀 Как вы можете внести вклад?

* **Сообщать об ошибках:** Нашли проблему в логике мультиинвентаря или UI? Откройте issue и предоставьте как можно больше контекста (логи, скриншоты, версию ОС).
* **Предлагать функции:** Есть идеи для генератора этикеток или экосистемы Kyro? Откройте обсуждение или issue с меткой `enhancement`.
* **Отправлять код:** Возьмите любую открытую issue с меткой `good first issue` или `help wanted`, сделайте форк репозитория и начинайте программировать.

## 🛠️ Настройка среды разработки

Чтобы запустить SOKO локально, убедитесь, что вы соблюдаете нашу архитектуру **Offline-First**, основанную на **Node.js, Electron и SQLite 3**:

1. Сделайте форк и клонируйте репозиторий.
2. Выполните `npm install`, чтобы получить все базовые зависимости.
3. Выполните `npm run rebuild sqlite3` (это крайне важно для компиляции нативных бинарных файлов).
4. Запустите среду разработки с помощью `npm start`.

## 🌿 Процесс Pull Request

* **Создайте ветку:** Создайте ветку от `main` с описательным именем (например, `feature/dark-mode-tweaks` или `fix/stock-transfer`).
* **Поймите основу:** Перед написанием кода прочитайте наши файлы `AGENTS.md` и `AI_CONTEXT.md`, чтобы полностью понять бизнес-логику, рекомендации по UI и строгость требований к базе данных.
* **Делайте чистые коммиты:** Пишите ясные и краткие сообщения коммитов.
* **Откройте PR:** Опишите внесённые изменения, проблему, которую они решают, и добавьте ссылки на связанные issue. Дождитесь проверки сопровождающих.

## 🎨 Руководства по стилю и соглашения

* **Эстетика UI/UX:** Любое визуальное дополнение должно соответствовать нативному *Dark Mode* и *cyber/tech* эстетике, ориентированной на стритвир.
* **Целостность базы данных:** Хранение тяжёлых изображений (BLOB) в базе данных строго запрещено; используйте пути к локальным файлам. Всегда соблюдайте реляционные ограничения и `PRAGMA foreign_keys = ON`.
* **Качество кода:** Сохраняйте модульность функций, комментируйте свои структурные решения и поддерживайте чистые отступы.
